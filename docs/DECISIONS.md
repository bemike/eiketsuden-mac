# 설계 결정 기록 (Decision Log)

되돌리기 어려운 결정만 기록합니다. 각 항목은 날짜 · 결정 · 검토한 대안 · 근거 순서입니다.

## D1. 언어와 엔진: Rust + macroquad (2026-09-24)

**결정**: 게임 엔진은 Rust로 작성하고 렌더링·입력·오디오는 [macroquad](https://github.com/not-fl3/macroquad) 0.4를 쓴다.
하나의 코드베이스에서 Windows / Linux / macOS 네이티브 실행 파일과 WebAssembly(브라우저) 빌드를 모두 만든다.

| 대안 | 장점 | 탈락 사유 |
|---|---|---|
| C++ + SDL2 + Emscripten (OpenRCT2와 동일) | 원조와 같은 구조 | 툴체인·빌드가 무겁고 웹 빌드 설정 비용이 큼 |
| TypeScript + Canvas + Electron | UI 개발 속도, 웹 우선 | 데스크톱 배포가 100MB+ Electron 번들, "EXE 대체"로서 무거움 |
| Go + Ebitengine | 단순, 크로스 컴파일 쉬움 | 개발 머신에 Go 툴체인 없음, 이점이 Rust 대비 크지 않음 |
| Godot 4 | 에디터·익스포트 완비 | 씬 파일 중심이라 데이터 주도 엔진 재구현과 성격이 다름, 바이너리 큼 |

**근거**: 원작 EXE를 대체하는 "엔진 재구현"(OpenRCT2 방식)이라는 목표에 네이티브 단일 실행 파일이 맞고,
같은 코드로 웹 라이브 데모를 만들 수 있다. 스파이크에서 Galmuri 폰트로 한글·한자 렌더링과
wasm32 빌드(약 630KB)가 브라우저에서 정상 동작함을 확인했다.

## D2. 코드 라이선스: GPL-3.0-or-later (2026-09-24)

**결정**: 엔진 코드는 GPL-3.0-or-later. **근거**: 참조 모델인 OpenRCT2와 같은 라이선스로, 재구현 프로젝트가 폐쇄 포크로 흡수되는 것을 막는다.
에셋은 각자의 라이선스(CC0 / CC-BY / OFL / 퍼블릭 도메인)를 따르며 `CREDITS.md`에 출처를 모두 적는다.

## D3. 에셋 정책: 원작 데이터는 저장소에 절대 포함하지 않는다 (2026-09-24)

**결정**: 저장소와 배포물에는 KOEI TECMO의 그래픽·음악·텍스트·실행 파일을 포함하지 않는다.
기본 콘텐츠("base pack")는 퍼블릭 도메인인 소설 『삼국지연의』를 바탕으로 새로 쓴 시나리오와
CC0 / CC-BY / OFL / 퍼블릭 도메인 에셋만으로 구성한다. 원작 데이터는 사용자가 정품을 보유한 경우에만
사용자 PC에서 읽어 쓰는 선택 기능으로 둔다(OpenRCT2가 RCT2 데이터를 요구하는 방식과 동일).

**근거**: 코드와 콘텐츠가 모두 재배포 가능한 라이선스여야 공개 저장소와 웹 데모가 법적으로 안전하다.
`.gitignore`에 `/data/original/`을 넣어 가져온 원작 데이터가 실수로 커밋되지 않게 한다.

## D4. 데이터 형식 (2026-09-24)

**결정**: 규칙·전투 데이터는 TOML, 대화 장면은 전용 `.drama` 스크립트, 이미지는 PNG, 음악·효과음은 OGG/WAV,
세이브는 버전 필드를 가진 JSON. **근거**: 사람이 직접 편집(모딩)하기 쉽고 serde로 검증 가능하며,
웹과 네이티브에서 같은 파일을 그대로 읽을 수 있다. 세이브 형식은 `version` 필드로 이후 마이그레이션을 허용한다.

## D5. 공개 저장소와 웹 데모 (2026-09-26)

**결정**: 저장소를 public으로 공개하고 GitHub Pages에 웹 라이브 데모를 올린다.

**근거**: 라이선스 점검 결과 공개에 걸림돌이 없다.

* 코드는 전부 새로 작성했다(GPL-3.0-or-later).
* 미디어는 CC0 / CC-BY / OFL / 퍼블릭 도메인만 쓰며 `CREDITS.md`에 출처를 모두 적었다.
* 대사와 시나리오는 퍼블릭 도메인 소설 『삼국지연의』를 바탕으로 새로 썼다.
* 원작에서 KOEI가 창작한 오리지널 무장은 역사 인물이나 이 리메이크의 창작 인물로 바꿨다.

원작의 규칙과 수치는 저작권 보호 대상이 아닌 사실 정보로 보고 재현한다. "영걸전(英傑伝)" 명칭은 OpenRCT2·OpenTTD처럼 원작을 가리키는 설명 목적으로만 쓴다. README에 KOEI TECMO와 무관하다는 고지를 넣고, 로고·트레이드 드레스는 쓰지 않는다.

**대안**: private으로 보관 후 공개(웹 데모 없음). 라이선스 위험이 확인되지 않아 채택하지 않았다.

## D6. 원작 데이터 임포터: 별도 선택 크레이트 + 미디어 오버레이 (2026-09-26)

**결정**: 정품 보유자용 임포터는 게임과 분리된 `crates/hero-import` 라이브러리와 `hero-tools original probe|extract`
명령으로 둔다. 결과물은 사용자가 고른 로컬 폴더에 **미디어 오버레이**(PNG + UTF-8 JSON + `index.json`)로 쓰고,
게임은 `--original <dir>`(네이티브 전용)일 때 미디어를 오버레이 → 팩 순서로 찾는다. 공유용 프로브 매니페스트
(`eiketsuden-original-probe` v1)와 오버레이 인덱스(`eiketsuden-original-overlay` v1)는 `format_version`을 가진
JSON이다. 새 의존성은 `encoding_rs`(EUC-KR/Big5), `sha2`(해시), `png`(이미 macroquad 경유로 잠금 파일에 있음)뿐이다.
자세한 내용은 [ORIGINAL_DATA.md](ORIGINAL_DATA.md).

| 대안 | 탈락 사유 |
|---|---|
| 게임 실행 파일 안에서 원작 파일을 직접 읽기 | 웹 빌드 크기 증가, 파서 오류가 게임 실행 경로에 들어옴, 원작 판본 차이를 매 실행마다 처리해야 함 |
| 원작 데이터를 완전한 데이터 팩으로 변환 | 맵·시나리오·규칙 형식이 아직 규명되지 않아(P4–P6) v1에서 불가능 |
| 사용자 데이터 폴더에 자동 저장 | 출력 위치를 사용자가 명시(`--out`)해야 저장소·설치 폴더에 실수로 쓰는 일을 막기 쉬움 |
| 인코딩 표·해시를 직접 구현 | 검증된 MIT/Apache 크레이트가 더 안전하고 작음 |

**근거**: D3(원작 데이터 비포함) 원칙을 유지하면서 OpenRCT2식 선택 기능을 제공한다. 클린룸(조사 노트의 사실만
사용, 타 프로젝트 코드 미사용), 읽기 전용, 업로드 없음, 복제 방지 우회 금지, 저장소·CI에 원작 바이트 없음(합성
픽스처와 환경 변수로만 도는 골든 테스트)을 지킨다. 문서로 확정되지 않은 형식(TF-DCE 얼굴, `BAKDATA` 배치)은
추측하지 않고 "지원 안 함"으로 보고한다.

## D7. 콘텐츠 라이선스: 기본 팩의 텍스트·데이터는 CC BY-SA 4.0 (2026-09-26)

**결정**: 기본 팩(`data/base`)의 텍스트·데이터 파일 — `pack.toml`, `officers.toml`, `campaign.toml`,
`rules/*.toml`, `battles/*.toml`, `dramas/*.drama`, `credits.txt` — 은
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)으로 배포한다. 엔진·도구 코드는 D2대로
GPL-3.0-or-later, 미디어(`gfx`, `sfx`, `bgm`, `fonts`)는 출처별 라이선스를 따른다. `CREDITS.md`의 "Licences"
표가 이 구분의 기준이고, `pack.toml`의 `license`와 `credits.txt`가 같은 내용을 적는다.

| 대안 | 장점 | 탈락 사유 |
|---|---|---|
| 저장소 전체를 GPL-3.0으로 두기 | 라이선스가 하나 | GPL은 소프트웨어용이라 대사·시나리오를 쓰는 2차 창작(소설, 위키, 다른 게임의 팩)에 조건이 맞지 않고, 이미 `pack.toml`·`credits.txt`가 CC BY-SA 4.0이라 적어 둔 것과 충돌한다 |
| CC BY 4.0 | 재사용 조건이 가장 가벼움 | 개작본이 닫힌 라이선스로 흡수될 수 있어 D2(GPL 선택)의 취지와 어긋난다 |
| CC0 | 제약 없음 | 출처 표시조차 요구할 수 없어 기여자 크레디트가 사라진다 |

**근거**: 텍스트 콘텐츠에 맞는 카피레프트 라이선스로, 코드의 GPL과 같은 "개작도 같은 조건으로" 원칙을 지킨다.
CC BY-SA 4.0은 GPL-3.0과 단방향 호환(CC BY-SA 4.0 → GPLv3)이라 팩 데이터를 GPL 코드에 넣어야 할 때도 막히지 않는다.
공개 전에 파일마다 서로 다른 조건이 보이지 않도록 한 번 정해 두며, 기여자가 늘어난 뒤에는 바꾸기 어렵다.

## D8. 팩 레이어링: `extends`로 다른 팩 위에 얹는 팩 (2026-09-26)

**결정**: `pack.toml`에 `extends = "<상대 디렉터리>"`를 두면 그 팩(부모) 위에 얹히는 자식 팩이 된다. 자식은 자기가
제공하는 파일만 적는다. 규칙 파일 다섯 개·`officers`·`campaign`은 가장 가까운 팩의 것이 **파일 단위로 대체**되고,
전투와 대사 장면은 **모든 팩의 합집합**이며 같은 전투 id·장면 id는 가까운 팩이 덮어쓴다(한 팩 안에서는 여전히
중복 금지). 미디어(`gfx/`, `bgm/`, `sfx/`, `fonts/`)는 최상위 팩부터 부모 순으로 찾고, 미디어 색인 파일도 파일 단위로
대체된다. 경로는 최상위 팩 기준으로 **어휘적으로**(`..`는 앞 구간 제거, URL과 동일) 풀고, 체인은 최대 4개 팩,
순환·없는 부모·체인 안의 같은 팩 `id`는 로드 오류다. 같은 결정의 일부로 `[presentation] canvas = [w, h]`
(기본 480×270, 320×200..1280×800)를 두고, 이 값은 가장 가까운 선언 팩에서 상속한다. 세이브는 최상위 팩의
`id`를 기억한다. 규칙은 [MODDING.md](MODDING.md#layered-packs-extends)에 있다.

| 대안 | 장점 | 탈락 사유 |
|---|---|---|
| 완전한 팩만 허용(부모를 통째로 복사) | 규칙이 가장 단순 | 원작 모드·밸런스 모드마다 기본 팩 전체를 복제해야 하고, 기본 팩이 고쳐져도 복제본에 반영되지 않는다. 원작 모드를 에셋 하나씩 늘려 가는 방식이 불가능 |
| D6의 미디어 오버레이만 확장 | 이미 있음, 게임 쪽 변경 없음 | 미디어만 바꿀 수 있어 규칙·맵·시나리오·캔버스 크기를 원작 것으로 바꿀 길이 없다. 오버레이 위치가 팩 밖(실행 옵션)에 있어 팩만 보고는 무엇이 로드되는지 알 수 없다 |
| 모든 파일을 항목 단위로 병합(자식 `items.toml`이 아이템 몇 개만 추가·수정) | 작은 모드에 편함 | 삭제 표현, 순서(지형 표시 순서·승급 체인) 의미, 검증 문맥이 모호해진다. 전투·장면처럼 원래 id 하나가 한 단위인 것만 id 단위로 합치고 나머지는 파일 단위 대체로 한정 |
| 실행 시 여러 팩을 순서대로 지정(`--data a --data b`, 모드 로드 순서) | 조합이 자유로움 | 조합이 팩 밖에 있어 재현·검증·세이브 호환 판단이 어렵고, 웹 빌드에는 명령줄이 없다 |
| 절대 경로·URL `extends` | 어디에 있든 참조 가능 | 팩 폴더를 옮기면 깨지고 웹 빌드(상대 URL fetch)에서 동작하지 않는다. 대신 원작 모드 팩은 기본 팩 옆(`data/original/`)에 두는 것으로 정한다 |
| 체인 깊이 무제한 | 제약 없음 | 순환 오류 메시지가 늦어지고 실사용 사례(원작 모드 위의 모드 정도)는 3단이면 충분. 4로 제한 |

**근거**: "원작 모드"(원작 에셋으로 그리는 모드)는 원작 형식이 규명되는 대로 에셋을 하나씩 바꿔 가야 하므로, 아직
변환하지 못한 모든 것을 라이선스 청정 기본 팩에서 가져올 수 있는 구조가 필요하다. 같은 구조가 일반 모드(밸런스
조정, 전투 추가)에도 그대로 쓰인다. 로딩은 웹을 위해 2단계를 유지한다: `pack.toml`을 하나씩 읽어 체인을
완성(`PackChain`)한 뒤 필요한 `(팩 디렉터리, 경로)` 전체를 나열하고, 그 파일들로 `Pack::load`를 호출한다.
`pack.toml` 필드·세이브 호환에 영향을 주는 결정이라 기록한다. 알려진 한계: 웹 빌드는 파일 존재를 fetch 없이
확인할 수 없어, 전투 화면이 `DataRoot::path`로 읽는 미디어 색인(`units.toml`·`terrain.toml`·`fx.toml`)과
`credits.txt`는 웹에서 최상위 팩 것만 읽는다(네이티브는 체인 순으로 찾는다).

## D9. 맵 파일과 그림 층 (2026-09-28)

**결정**: 전투 맵에 **그림 층**을 둔다. `[map] image = "<키>"`이면 맵 전체를 그린 그림 한 장
`gfx/maps/<키>.png`를 타일셋 대신 그리고, `rows`는 그대로 **규칙 층**(이동·방어·회복·책략)이다. 그림 크기는 정확히
맵 칸 수 × 타일셋 `tile_size`여야 하며, 없거나 크기가 다르면 게임은 경고를 남기고 타일셋으로 그리고
`hero-tools validate`는 오류로 보고한다. 같은 결정의 일부로 전투와 떨어진 **맵 파일**을 둔다. `pack.toml`의
`maps = [...]` 파일에 `[[map]]`(`id`, `name`, `rows`, `legend`, `theme`, `image`)을 적고, 전투는 `[map] use = "<id>"`로
참조하며 `use`와 다른 맵 필드를 함께 쓸 수 없다. 레이어드 팩에서 맵은 전투·장면처럼 **합집합 + 가까운 팩 우선**이고,
`use`는 체인 전체를 합친 뒤 풀리므로 자식 팩의 맵이 부모 전투의 맵도 바꾼다. `Pack::load`가 `use`를 풀어
전투 정의에 맵을 복사하므로 전투 규칙·세이브·AI는 바뀌지 않는다. 규칙은 [MODDING.md](MODDING.md#map-files),
그림 규격은 [ASSETS.md](ASSETS.md#map-pictures--gfxmapskeypng)에 있다.

| 대안 | 장점 | 탈락 사유 |
|---|---|---|
| 그림 층 없이 타일셋만(학습 타일셋 개선) | 엔진 변경 없음 | 원작 맵은 칩이 대각선·부분 칸으로 이어져 칸 단위 타일로는 같은 그림이 나오지 않는다(BACKLOG "학습 타일셋의 경계 개선"). 원작 맵은 칩 격자 자체가 정답이다 |
| 원작 칩 격자(16 px)를 엔진 맵 격자로 | 칩을 그대로 쓸 수 있음 | 원작의 이동 격자는 2×2 칩 칸(32 px)이라 규칙 격자와 그림 격자가 다르다. 엔진에 두 격자를 들이는 대신 칩을 미리 그림으로 합친다 |
| 그림을 칸 단위 조각으로 자른 아틀라스 | 기존 타일셋 경로 재사용 | 58개 맵이 거의 모든 칸마다 다른 조각을 만들어 아틀라스가 커지고, 맵마다 전용 타일 키가 필요해 지형 규칙과 섞인다 |
| 맵 파일 없이 전투 파일에만 맵 | 형식 추가 없음 | 원작 맵은 시나리오 변환(STATUS 4절 2단계)보다 먼저 변환·검증할 수 있는데, 쓰는 전투가 없으면 팩에 둘 곳이 없다. 같은 맵을 여러 전투가 쓰는 경우에도 복사가 필요하다 |
| 맵 파일 하나에 맵 하나 | 파일이 작음 | 원작 모드가 58개 파일을 쓰게 되고, 드라마 파일처럼 여러 항목을 담는 편이 목록 관리가 쉽다 |
| 쓰지 않는 맵은 경고 | 실수를 찾기 쉬움 | 원작 모드 팩은 전투보다 맵이 먼저 들어가므로 경고 58개가 상시 나온다. 검증은 모든 맵에 똑같이 하되 미사용은 경고하지 않는다 |

**근거**: 원작 모드는 원작 전투를 원작 맵 위에서 해야 하는데(STATUS 4절 1단계 "원작 맵"), 원작 맵의 모습은 칩 격자,
규칙은 칸마다의 지형 바이트다. 이 둘을 그림 층과 규칙 층으로 나누면 엔진은 규칙 격자만 알면 되고, 모드도 손으로 그린
맵 그림을 쓸 수 있다. `pack.toml` 필드와 전투 형식에 영향을 주는 결정이라 기록한다. 세이브에는 맵 격자(`BattleMap`)만
저장되고 그림은 전투 정의에서 오므로 세이브 형식은 바뀌지 않는다.
