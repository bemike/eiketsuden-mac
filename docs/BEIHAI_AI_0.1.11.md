# 北海之战 AI 修复：Mac 0.1.11

## 原因及修改

管亥的原版名册 AI 是模式 6（无攻击行军），从 `(6,7)` 前往 `(7,10)`。移植引擎到达后永久待命，因而赵云无法在骑兵不能进入的山区与他接触。

核对繁体中文 DOS `MAIN.EXE` 后确认：坐标行军抵达目的地并结束行动后，内部 AI 0/4 会转换为 3（待机迎敌）。代码地址与来源哈希见 [FORMATS §13.4](reverse-engineering/FORMATS.md#中文-dos-版到达目的地后的-ai-状态转换代码验证)。

0.1.11 原版资源包启用 `ai_defend_on_arrival`。已经抵达的旧存档也按待机迎敌规划；成功行动后保存新状态，不会再次返回原行军点。刚抵达的无攻击行军单位在该回合仍然待命。按武将目标行军、自制基础包和骑兵地形限制保持原行为。

## 验证结果

- 工作区测试：767 通过，0 失败；2 个已有文档示例忽略。新增覆盖到达回合、旧存档规划及持久化、坐标推进、武将目标行军、拒绝动作不修改状态。
- 完整中文原版资源包重新转换并校验：0 错误；1 个既有基础演示关卡未用于原版战役的警告。
- `verify_beihai_ai` 只读取旧存档的副本，保留原地图及管亥的旧 AI，把其他单位暂时隐藏以隔离单挑。将赵云置于骑兵可进入的 `(7,15)` 后，管亥合法移动至 `(7,14)`：单挑事件触发一次、赵云升一级、管亥撤退、战斗胜利。
- 原版事件回归检查通过：广川关羽／逢纪接触与升级、旧存档事件兼容及不重播、许昌后续地图、神秘人物事件，以及 113 个已转换接触事件。
- 最终 ZIP 解压应用内验证：用独立应用标识和独立存档目录载入同一复现场景；结束我方回合后看到管亥下山、赵云／管亥单挑对白、原版单挑图片。没有操作用户正在运行的游戏窗口或改写真实存档。
- arm64 构建、打包字体检查、临时干净目录中的严格代码签名检查、ZIP CRC 检查通过。

此验证覆盖该地形与旧 AI 状态，并非声称所有战役已逐关人工通关。

## 本地复现

```sh
cargo run --release -p hero-tools --example verify_beihai_ai --   /path/to/converted-original-pack /path/to/copied-beihai-save.json
```

可选第三个参数写出独立 UI 测试存档。输入存档始终只读，例程验证输入字节未改变。真实存档、测试副本及原版程序反汇编不提交到仓库。
